# Wayveil: десктоп-приложение для VLESS + REALITY со сплит-туннелированием (дизайн)

*Дата: 2026-11-07. Статус: черновик на согласование.*

## 1. Зачем

Автор поднимал свой сервер скриптом [ndatg/xray-vless-reality-installer](https://github.com/ndatg/xray-vless-reality-installer) (MIT). Серверная часть устраивает. Больное место — клиент: сплит-туннелирования «из коробки» нет, v2rayA перегружен настройками и работал нестабильно.

Нужно одно небольшое приятное приложение для Windows и Linux, которое:

1. **Владельцу VPS** поднимает VLESS + REALITY + Vision на свежем сервере по SSH, помогает выбрать таргет (маскировочный сайт) и даёт управлять друзьями-клиентами.
2. **Другу** даёт вставить ссылку и нажать одну кнопку: заблокированное в РФ идёт через туннель, остальное напрямую.

Проект открытый, будет опубликован на GitHub. Цель — набрать звёзды, поэтому первое впечатление и «работает с первого раза» важнее гибкости.

### Кто пользуется

- **Владелец сервера.** Только что купил VPS, разбирается немного или вообще не разбирается. Вводит IP и пароль, проходит мастер, раздаёт ссылки друзьям.
- **Друг.** Ничего не настраивает и не хочет. Получил ссылку или QR, вставил, нажал «Подключиться».

Это одно приложение. Роль определяется тем, есть ли в нём сохранённый собственный сервер.

## 2. Цели, не-цели, анти-цели

**Цели (v1)**
- Установка сервера по SSH в мастере из 3 шагов с живым прогрессом.
- Помощь с таргетом: объяснение, готовые варианты, проверка своего домена, предупреждение и альтернативы.
- Полное удаление всего установленного с сервера одной кнопкой (по манифесту), без Docker.
- Управление клиентами: добавить, удалить, перевыпустить ключ, ссылка и QR, трафик по каждому, последний вход и IP.
- Клиент со сплит-туннелированием в системном TUN-режиме по автообновляемым спискам (реестр РКН и сервисы, закрытые для РФ).
- Свои правила «всегда через VPN / всегда напрямую» и переключатель «всё через VPN».
- Сборки: Windows (.exe-установщик), Linux (.AppImage, .deb).
- Интерфейс на русском и английском.

**Не-цели (v1)**
- Мобильные приложения, macOS.
- Лимиты трафика, ограничение числа устройств или IP на ключ. *Обсуждали и отказались: даёт ложные срабатывания.*
- Несколько серверов, выбор сервера под конкретный сайт, тонкая настройка маршрутов.
- Транспорт XHTTP (есть в исходном скрипте). В v1 только TCP + XTLS Vision.
- Привязка ключа к устройству или MAC. *Сервер MAC не видит физически, пользователю это объяснили.*

**Анти-цели (провал, даже если «технически работает»)**
- Приложение превратилось во второй v2rayA с десятками настроек.
- Подключение «работает через раз».
- Российские сайты (банки, Госуслуги, маркетплейсы) идут через зарубежный IP и ломаются.
- DNS-утечки или подмена DNS провайдером, из-за которых «VPN включён, а сайт не открывается».
- Окно открывается на весь экран или выглядит как админка.

## 3. Решения автора (зафиксировано)

- **Стек:** Wails (Go-бэкенд + веб-интерфейс). На клиенте **sing-box**, на сервере **xray**.
- **Визуальный стиль:** тёмный минимализм, вариант A из макетов: тёмно-синий радиальный градиент (`#1e2a4a → #0b0f1a`), главная круглая кнопка с градиентом `#3b82f6 → #8b5cf6` и свечением, полупрозрачные карточки `rgba(255,255,255,.06)`, системный шрифт. Макеты: `.superpowers/brainstorm/*/content/visual-style.html` (вариант A) и `owner-screens.html`.
- **Окно:** компактное, «как телефон», примерно 380×640, **не** разворачивается на весь экран по умолчанию. Навигация — нижние вкладки: «Подключение», «Сервер» (только у владельца), «Настройки».
- **Таргет:** короткое объяснение человеческим языком, список готовых вариантов в один клик (автор назвал ozon.ru и vk.com), поле для своего домена. Если домен не подходит (нет TLS 1.3 и т.п.), появляется предупреждение с причиной и предлагаются альтернативы.
- **Сплит-туннелирование:** через туннель идут сайты из реестра РКН и сервисы, которые сами закрыли доступ из РФ (ChatGPT, Claude, Spotify, Notion…). Всё остальное напрямую. Системный TUN, через туннель ходят все приложения (Telegram, Discord, лаунчеры). Списки обновляются сами.
- **Клиенты на сервере:** добавить, удалить, перевыпустить ключ, трафик по каждому, последний IP и время входа. Без лимитов по IP.
- Остальное из раздела 4 автор подтвердил как разумные значения по умолчанию.

## 4. Как это устроено

### 4.1 Общая схема

```
┌──────────── Приложение (Wails) ────────────┐          ┌──────── VPS ────────┐
│ UI (Svelte/TS)  ⇄  Go-бэкенд               │  SSH     │ xray (systemd)       │
│                     ├─ provisioner ────────┼─────────▶│ /etc/xray/config.json│
│                     ├─ server manager      │          │ stats API (local)    │
│                     ├─ rules updater       │          │ access log           │
│                     └─ sing-box controller │          └──────────────────────┘
│                          │                 │                   ▲
│                    sing-box (TUN) ─────────┼── VLESS+REALITY ──┘
└────────────────────────────────────────────┘
```

### 4.2 Установка сервера (мастер владельца)

**Шаг 1 — доступ.** IP или хост, порт SSH (по умолчанию 22), пользователь (по умолчанию root), пароль **или** приватный ключ. Подключение через `golang.org/x/crypto/ssh`. Отпечаток хоста показывается при первом подключении (TOFU) и затем запоминается.

- Сразу после входа приложение генерирует свою пару ключей ed25519, добавляет публичный ключ в `authorized_keys` и дальше ходит только по нему. **Пароль нигде не сохраняется.**
- Проверяется ОС. Поддерживаются Ubuntu 22.04/24.04 и Debian 11/12. Остальные ОС получают понятный отказ. Проверяется, что порт 443 не занят.

**Шаг 2 — таргет.** См. 4.3.

**Шаг 3 — установка** с живым прогрессом (шаги с галочками и раскрывающийся лог):

- За основу берётся `xray-install.sh` из исходного репозитория (MIT, сохранить копирайт в `THIRD_PARTY_LICENSES`). Он переписывается в **неинтерактивный** вариант: параметры передаются флагами или переменными, прогресс выводится машиночитаемыми строками (например, `##STEP <id> <status>`). Скрипт вшит в бинарник (`embed`), заливается по SSH и запускается.
- Логику исходника сохраняем: установка xray-core, ключи REALITY, short id, systemd-юнит на 443, валидация конфига перед заменой, блокировка приватных адресов, BBR.
- Сверх исходника:
  - включаются **stats API** xray: `api` + `StatsService`, inbound `dokodemo-door` на `127.0.0.1`, `policy.levels.0.statsUserUplink/Downlink = true`;
  - включается **access log** с `email` клиентов и ротация через logrotate (хранить ≤ 7 дней);
  - кладётся файл-маркер `/etc/xray/wayveil.json` с версией схемы, адресом сервера, таргетом и публичным ключом.
- В конце автоматически создаётся первый клиент «Я» и сразу импортируется в само приложение, чтобы владелец тоже был подключённым клиентом.

**Без Docker (решение автора).** Ставим нативно через systemd, как исходный скрипт. Docker обсуждали (как у AmneziaVPN) и отказались: лишние минуты установки и сотни мегабайт на диске, не работает на части дешёвых OpenVZ/LXC VPS, усложняет статистику и логи. Чистоту удаления обеспечивает манифест (ниже).

**Манифест и полное удаление.** Установщик ведёт на сервере манифест `/etc/xray/wayveil-manifest.json`: каждый созданный файл и каталог (бинарник xray, `/etc/xray`, systemd-юнит, sysctl-файл BBR, конфиг logrotate, логи), каждое изменение существующих файлов с исходным значением (строка ключа приложения в `authorized_keys`), созданный системный пользователь, установленные через apt пакеты (только те, которых не было до установки). На вкладке «Сервер» есть кнопка **«Удалить Wayveil с сервера»** с подтверждением: остановить и отключить сервис, удалить всё по манифесту в обратном порядке, откатить sysctl, убрать свой ключ из `authorized_keys` последним шагом. После этого сервер в приложении забывается, а клиенты на нём перестают работать (приложение об этом предупреждает). Удаление идемпотентно: при повторном запуске после обрыва связи оно доделывает оставшееся. Без SSH-доступа на сервер можно выполнить то же самое вручную: вшитый скрипт удаления копируется на сервер при установке (`/etc/xray/wayveil-uninstall.sh`), и в README описана одна команда для запуска.

**Повторная установка / уже установлено.** Если на сервере найден `wayveil.json`, приложение предлагает «подключиться к существующему» (взять управление) или «переустановить». Если там стоит xray, установленный исходным скриптом, без маркера, — предлагается переустановка с предупреждением, что старые ссылки перестанут работать. *Миграция существующих клиентов — желательно, но не обязательно для v1 (решение за исполнителем).*

### 4.3 Таргет

- **Пояснение на экране** (примерно): «Для провайдера ваш трафик будет выглядеть как обычный заход на этот сайт. Подойдёт популярный сайт с современным шифрованием».
- **Как подбираются варианты (решение автора):**
  1. **Сначала — зарубежные сайты из той же сети, что и VPS.** Приложение определяет сеть сервера (ASN или подсеть по IP) и ищет в ней публичные HTTPS-сайты, которые проходят проверку. Источник кандидатов выбирает исполнитель: например, сканирование соседних IP подсети с чтением SNI/SAN из сертификата (в духе RealiTLScanner) или справочник ASN → домены. Найденные подходящие помечаются «рекомендуем».
  2. **Если в сети сервера никого подходящего нет** — предлагаются проверенные зарубежные сайты из той же страны, что и VPS (например, для Нидерландов — нидерландские), из вшитого обновляемого списка `rules/targets.json`, сгруппированного по странам.
  3. **Всегда, отдельной строкой ниже** — российские варианты (ozon.ru, vk.com и др.) с подписью, например: «Также можно: ozon.ru, vk.com — российские сайты, на зарубежном сервере маскировка может быть заметнее».
  - Пользователь выбирает сам. Ни один вариант не навязывается, «рекомендуем» — это только подсказка.
- **Скорость поиска в сети сервера (требование автора: пользователь не должен ждать):**
  - Поиск **запускается в фоне сразу после успешного SSH-входа** (шаг 1), параллельно с проверкой ОС, пока пользователь читает экран таргета.
  - Сканирование идёт **на самом сервере**, а не с ПК пользователя: сервер находится в той же сети, задержки там минимальные, а с ПК пришлось бы идти через границу и, возможно, через блокировки. Заливается маленький статический сканер (Go, вшит в приложение, сборки amd64/arm64) с параллельными TLS-рукопожатиями (десятки или сотни одновременно), коротким таймаутом (~1–2 с на адрес) и ограничением диапазона (своя /24, затем соседние).
  - **Результаты стримятся построчно**: на экране сразу видны запасные варианты (страна сервера + российские), а найденные в сети сервера появляются сверху по мере нахождения с плашкой «рекомендуем». Индикатор «ищем сайты рядом с сервером…» не блокирует кнопку «Далее».
  - Жёсткий лимит времени (~30 с) и найденных кандидатов (например, первые 5 прошедших полную проверку). После этого сканер останавливается и удаляется с сервера.
  - Результат кешируется в `wayveil.json`: при смене таргета позже поиск не повторяется (есть кнопка «искать заново»).
- Каждый вариант **перед показом проверяется с сервера**, неподходящие скрываются.
- **Проверка своего домена выполняется на сервере** (а не с ПК пользователя), повторяя `check_sni_target` из исходника: `curl --tlsv1.3 --http2` → нужны ответ, HTTP/2, отсутствие редиректа на другой домен. Дополнительно — время TLS-рукопожатия: показать, если очень медленно.
- **Если не подходит:** жёлтое предупреждение с причиной простыми словами («не поддерживает TLS 1.3, маскировка не сработает») и 2–3 подходящих варианта. Продолжить всё равно можно (кнопка «Использовать всё равно»), но по умолчанию предлагается альтернатива.
- Таргет можно сменить позже на вкладке «Сервер». Ссылки клиентов при этом меняются, приложение предупреждает об этом.
- Почему именно такой порядок: исходный README рекомендует *зарубежный* сайт в той же сети, что и VPS, а российские домены на зарубежном IP потенциально легче вычислить.

### 4.4 Управление клиентами (вкладка «Сервер»)

- **Источник правды — конфиг xray на сервере.** Клиент xray = `{id: UUID, email: <внутренний id>, flow: "xtls-rprx-vision"}`. Отображаемое имя хранится в `wayveil.json` (или кодируется в `email`). Приложение не хранит своего списка, а читает его с сервера. Так владелец не теряет данные при переустановке приложения или работе с другого ПК; для этого нужен SSH-доступ, приложение умеет «подключиться к существующему серверу» по паролю или ключу.
- **Изменения:** `jq`-правка во временный файл → `xray run -test` → атомарная замена → `systemctl restart xray`. При ошибке старый конфиг остаётся.
- **Список (экран 1):** имя, время и IP последнего входа, суммарный трафик, кнопка «+ Добавить друга» (спрашивает только имя).
- **Карточка (экран 2):** QR, «Копировать ссылку», «Сохранить QR», трафик ↓/↑, последний вход, последний IP, «Перевыпустить ключ» (новый UUID, старый сразу перестаёт работать), «Удалить» (с подтверждением).
- **Трафик:** `xray api statsquery` по SSH. Счётчики xray обнуляются при рестарте, поэтому приложение при каждом опросе добавляет дельту к накопленному итогу, который хранится на сервере (в `wayveil.json` или рядом). Перезапуск xray не должен обнулять видимые цифры.
- **Последний вход и IP:** разбор access log (`email` + исходный IP + время) по SSH, берётся последняя запись по каждому клиенту.
- Обновление при открытии вкладки и кнопкой «обновить»; фоновый опрос не обязателен.
- **Ссылка:** стандартная `vless://UUID@host:443?security=reality&sni=…&fp=chrome&pbk=…&sid=…&flow=xtls-rprx-vision&type=tcp#Имя`. Она совместима с v2rayNG, Hiddify, Shadowrocket и т.п. на телефонах.

### 4.5 Клиент (вкладка «Подключение»)

**Первый запуск без профиля:** экран «Вставьте ссылку от друга» с полем, кнопкой «Вставить из буфера» и «Открыть картинку с QR» (декодирование QR в Go). Ниже — ссылка «У меня есть свой сервер → настроить», ведущая в мастер владельца.

**Главный экран (макет A):** большая круглая кнопка; статус («Подключено» / «Отключено» / «Подключаюсь…» / ошибка понятными словами); страна сервера (GeoIP по IP сервера, необязательно) и таймер; карточки «Загружено» и «Режим: Умный / Всё через VPN».

**Движок:** sing-box как отдельный бинарник, вшитый в сборку под каждую ОС. Go-бэкенд генерирует конфиг, запускает и останавливает процесс, читает статистику через Clash API sing-box (только на `127.0.0.1` с секретом).

- **Inbound:** `tun` с `auto_route` и `strict_route` (точные параметры подбирает исполнитель под Windows и Linux), `stack` по умолчанию.
- **Outbound:** `vless` + `tls.reality` + `utls: chrome` + `flow: xtls-rprx-vision`; `direct`.
- **Маршрутизация («Умный» режим):**
  1. приватные сети и сам IP сервера → direct;
  2. пользовательские «всегда напрямую» → direct;
  3. пользовательские «всегда через VPN» → proxy;
  4. rule-set «заблокировано в РФ» + «сервисы, закрывшие доступ для РФ» (домены и IP) → proxy;
  5. всё остальное → direct.
- **Режим «Всё через VPN»:** всё → proxy, кроме приватных сетей и IP сервера.
- **DNS:** для доменов из proxy-списков — DNS через туннель (DoH к 1.1.1.1 или 8.8.8.8 через proxy outbound). Для остального — обычный DNS (DoH к 77.88.8.8 или системный). Цель — исключить подмену DNS провайдером для заблокированных доменов и не отправлять за рубеж запросы российских сайтов. Конкретная схема (fakeip или нет) — на усмотрение исполнителя, главное — критерии приёмки из раздела 7.
- **Списки:** основной источник — [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains) (есть и «заблокированное», и «закрыто для РФ»), для IP — antifilter или аналог. Используются готовые `.srs` для sing-box, если они есть; иначе приложение конвертирует сам. Обновление при запуске и раз в сутки с кешем на диске. Без сети работает на кешированной версии, а в сборку вшита стартовая копия, чтобы первое подключение не зависело от GitHub. *Исполнитель проверяет актуальность и формат источников.*

**Права администратора.** TUN требует повышенных прав. Ограничение: **запрос прав не чаще одного раза — при установке или первом подключении**, а не при каждом нажатии кнопки.
- Windows: установщик (NSIS через Wails) ставит маленькую службу-помощника, которая запускает sing-box. GUI работает без админ-прав и общается со службой по named pipe с проверкой, кто подключился.
- Linux: `.deb` при установке выдаёт `cap_net_admin` бинарнику sing-box (`setcap`) или ставит systemd-юнит. Для AppImage при первом подключении — однократный `pkexec`.
- Конкретная реализация — на усмотрение исполнителя в рамках ограничения выше.

### 4.6 Настройки

- Свои правила: два списка доменов, «всегда через VPN» и «всегда напрямую», добавление одной строкой.
- Режим: Умный / Всё через VPN.
- Автозапуск с системой (выкл по умолчанию), «подключаться при запуске».
- Язык: русский / английский (по умолчанию — по языку системы).
- «Обновить списки сейчас», дата последнего обновления.
- Профиль подключения: показать ссылку, заменить ссылку, удалить.
- О программе: версия, ссылка на GitHub, проверка обновлений.

### 4.7 Окно, трей, обновления

- Окно примерно 380×640, без «развернуть на весь экран» по умолчанию; положение запоминается.
- Иконка в трее с состоянием (подключено / нет). Меню трея: Подключить/Отключить, Открыть, Выход. Закрытие окна сворачивает в трей, полный выход — через меню трея.
- Проверка новой версии через GitHub Releases API при запуске. Показывается баннер «Доступна версия X» со ссылкой; автоустановка в v1 не обязательна.

### 4.8 Хранение данных на клиенте

- Каталог конфигурации ОС (`%APPDATA%\Wayveil`, `~/.config/wayveil`): профиль подключения, свои правила, настройки, кеш списков.
- SSH-ключ владельца и данные сервера — там же, с правами 0600 на Linux. На Windows ключ шифруется через DPAPI, на Linux — через keyring, если он доступен; иначе файл 0600.

### 4.9 Сборка и релизы

- Монорепо: `app/` (Wails), `server/` (вшитый скрипт установки), `rules/` (список готовых таргетов), `.github/workflows/`.
- GitHub Actions по тегу `v*`: Windows `.exe` (NSIS), Linux `.AppImage` и `.deb` (amd64; arm64 — по возможности). В сборку скачиваются sing-box нужной зафиксированной версии и стартовые списки.
- Подписи кода в v1 нет. В README честно описать предупреждение SmartScreen.
- README на английском (основной) и русском, со скриншотами и GIF «от покупки VPS до работающего VPN».

## 5. Остаётся на усмотрение исполнителя

**Решения, принятые за автора при проверке документа (можно оспорить):**
- **SSH:** поддерживается root или пользователь с беспарольным sudo (как в облачных образах Ubuntu). Остальным — понятное сообщение, что сделать.
- **Wails:** v3, если у неё есть стабильный релиз (встроенный трей). Иначе Wails v2 + отдельная библиотека трея.

Фреймворк фронтенда (Svelte или React), структура Go-пакетов, способ IPC с привилегированным помощником, точные параметры TUN и DNS в sing-box, источник GeoIP, формат хранения имён клиентов на сервере, миграция с исходного скрипта, механика опроса статистики — всё в рамках ограничений и критериев выше.

## 6. Риски и открытые вопросы

- Поиск сайтов в сети сервера может ничего не найти или работать медленно. Он должен укладываться в разумное время (≈30 с) с понятным индикатором и всегда переходить к запасным вариантам (4.3, п. 2–3).
- Источники списков могут поменять формат или исчезнуть. Нужен механизм смены URL без релиза (URL берутся из `rules/sources.json` в репозитории, с вшитым запасным вариантом).
- Без подписи кода Windows Defender и SmartScreen могут ругаться на `.exe`, тем более со службой и TUN-драйвером.

## 7. Критерии приёмки v1

1. На чистом VPS с Ubuntu 24.04 мастер от ввода пароля до готовой ссылки проходит без ручных действий, менее чем за 3 минуты.
2. Неподходящий таргет (без TLS 1.3 или с редиректом) даёт понятное предупреждение и альтернативы.
3. Добавленный друг подключается по ссылке и в этом приложении, и в v2rayNG или Hiddify. После «Удалить» или «Перевыпустить» старая ссылка перестаёт работать в течение нескольких секунд.
4. Трафик по клиенту растёт при использовании и не обнуляется после перезапуска xray.
5. В умном режиме при включённом VPN: youtube.com, instagram.com, chatgpt.com открываются; 2ip.ru показывает российский IP; gosuslugi.ru и сайт Сбера открываются напрямую.
6. DNS-запросы к заблокированным доменам не уходят к DNS провайдера в открытом виде (проверка через Wireshark или dnsleaktest при «всё через VPN»).
7. Telegram Desktop работает через туннель без настройки прокси в нём самом.
8. Права администратора запрашиваются не больше одного раза.
9. «Удалить Wayveil с сервера» на чистом Ubuntu 24.04 после установки не оставляет ничего: нет файлов, сервиса, sysctl-настроек, пользователя, ключа в `authorized_keys`. Порт 443 свободен, повторная установка с нуля проходит.
10. Окно компактное, интерфейс на ру/en, сборки для Windows и Linux публикуются CI по тегу.
