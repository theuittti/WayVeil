# Wayveil 3a: GUI — мастер установки сервера и подключение (Linux) — дизайн

*Дата: 2026-11-09. Статус: на согласование. Дополняет основную спеку
`2026-11-07-wayveil-design.md`. Всё, что там сказано про стиль, окно, мастер,
таргет и клиент, остаётся в силе. Здесь записано, что входит в первый этап
третьей стадии и какие решения приняты сверх спеки.*

## 1. Зачем и что именно

Первые две стадии сделали всю логику: установку сервера по SSH, подбор
таргета, управление клиентами, движок подключения на Linux. Сейчас ей можно
пользоваться только из CLI (`wayveil-dev`, `wayveil`). Третья стадия делает
приложение, ради которого всё затевалось.

**Решение автора: первым делаем мастер установки сервера, это главная часть
приложения.** Первый этап (3a) — **мастер + подключение, на Linux.** Цель
этапа: автор на своём Linux-компьютере запускает приложение, проходит мастер
на свежем VPS и подключается одной кнопкой, без терминала.

## 2. Цели, не-цели, анти-цели

**Цели 3a**
- Пять экранов мастера по одобренному макету
  (`.superpowers/brainstorm/651397-1794240238/content/wizard.html`):
  первый запуск → доступ → таргет → установка → готово.
- Главный экран подключения (макет A из основной спеки): большая кнопка,
  статус, таймер, режим «Умный / Всё через VPN».
- Пограничные случаи мастера (раздел 4.3), с понятными сообщениями.
- Сборка и запуск на Linux одной командой (`make app`).

**Не-цели 3a (следующие этапы)**
- Вкладка «Сервер» / управление устройствами (решение автора: следующий этап,
  будет называться «Добавить устройство»).
- Windows, служба-помощник, трей, автозапуск, установщики (.deb, AppImage,
  NSIS), CI-релизы, проверка обновлений.
- Экран настроек (свои правила, обновление списков вручную).
- Шифрование ключа владельца через keyring (пока файл 0600, как сейчас).

**Анти-цели**
- Пароль от VPS сохраняется где-либо или попадает в лог.
- GUI дублирует серверную логику вместо вызова готовых пакетов
  `internal/server`, `internal/engine` и т.д.
- Мастер блокирует пользователя ожиданием (поиск таргета идёт в фоне,
  «Далее» доступна сразу).
- Права администратора запрашиваются больше одного раза.

## 3. Решения автора (в этом разговоре)

- Начинаем с мастера; первая платформа — Linux.
- Макет пяти экранов мастера одобрен («идеально»).
- **Интерфейс только на английском** (2026-11-09). Это отменяет ru/en из
  основной спеки (раздел 4.6 и критерий 10). Словаря переводов нет. Названия
  экранов и кнопок в этом документе даны по-русски только для описания;
  в приложении они английские.
- **Нейтральные формулировки:** первый экран — «Paste a connection link» с
  подсказкой `vless://…`, без «от друга». Ссылка «I have my own server →
  set up» остаётся внизу. В интерфейсе вместо «друга» — «устройство»
  (например, «+ Add device» на будущей вкладке). Первое устройство
  владельца называется «Me».
- Догадки про пограничные случаи (раздел 4.3) подтверждены автором.
- Объём 3a: мастер + подключение; вкладка устройств — следом.

## 4. Как устроено

### 4.1 Стек (решения исполнителя)

- **Wails v2** (стабильная ветка). Wails v3 на 2026-11-09 всё ещё в бете, а
  основная спека велит брать v3 только при стабильном релизе. Трей в 3a не
  нужен, так что отдельная библиотека трея тоже пока не нужна.
  На Linux — WebKitGTK 4.1 (тег сборки `webkit2_41`; в Ubuntu 24.04+ есть
  только 4.1).
- **Фронтенд: Svelte + TypeScript + Vite** (основная спека называет Svelte/TS).
  Стили — обычный CSS с переменными стиля A, без UI-библиотек.
- Код GUI: `cmd/wayveil-gui/` (main + Wails-обвязка) и `frontend/`.
  Go-методы, которые вызывает фронтенд, — в отдельном пакете
  `internal/gui` (структура `App`), чтобы их можно было тестировать без окна.
- mihomo и xray лежат рядом с бинарником GUI (как уже ищет `mihomo.Find` /
  `xrayclient.Find`); `make app` собирает `build/wayveil-gui` и кладёт рядом
  `build/mihomo`, `build/xray`.

### 4.2 Мастер: что делает каждый экран

Вся логика уже есть в `cmd/wayveil-dev` (`cmdInstall`) и пакетах
`internal/server`, `ownerstore`, `profile`, `engine`. `internal/gui.App`
повторяет тот же порядок вызовов, только с событиями для экрана вместо печати.

0. **Первый запуск** (нет сохранённого профиля подключения): поле ссылки,
   «Из буфера», «QR-картинка» (`profile.FromLink` / `FromQRImage`). Внизу —
   «У меня есть свой сервер → настроить». Если профиль есть — сразу главный
   экран подключения.
1. **Доступ:** хост, порт (22), пользователь (root), пароль или ключ.
   «Подключиться» → `sshx.Connect`. При первом подключении показывается
   отпечаток хоста и вопрос «это ваш сервер?» (TOFU, как в `wayveil-dev`).
   Затем `server.Precheck`. **Сразу после успешного входа в фоне стартует
   `SuggestTargets`**, результаты стримятся на экран таргета событиями.
   Пароль живёт только в памяти до конца вызова подключения.
2. **Таргет:** найденные рядом с сервером — сверху с плашкой «рекомендуем» по
   мере нахождения; запасные (страна сервера, затем `www.microsoft.com` и т.п.);
   строка с российскими вариантами; поле своего домена с проверкой
   `server.CheckTarget` и жёлтым предупреждением + 2–3 альтернативами, кнопка
   «Использовать всё равно». Индикатор поиска с секундами не блокирует «Далее».
3. **Установка:** генерация ключа приложения, **сохранение профиля владельца
   до установки** (`ownerstore.Save`, как в CLI — чтобы неудачную установку
   можно было убрать), `server.Install` с zip xray, вшитым в сборку
   (сервер не зависит от GitHub, как в e2e), шаги с галочками в
   человеческих названиях, раскрывающийся лог, таймер. Затем
   `AddClient("Me")` и `Info`.
4. **Готово:** QR и ссылка «Я», «Копировать ссылку», «Подключиться». Ссылка
   «Я» сохраняется как профиль подключения, т.е. владелец — тоже клиент.

### 4.3 Пограничные случаи (подтверждены автором)

| Что увидел Precheck / что случилось | Что показывает мастер |
|---|---|
| ОС не поддерживается | Отказ: какая ОС найдена, список поддерживаемых, совет переустановить ОС у хостера на Ubuntu 24.04 |
| Порт 443 занят | Отказ: каким процессом, совет освободить порт |
| Уже стоит Wayveil (`HasWayveil`) | Выбор: «Взять управление» (ключ приложения добавляется, новая установка не нужна, создаётся устройство «Я», мастер идёт сразу на «Готово») или «Переустановить» (Uninstall → Install, с предупреждением, что старые ссылки перестанут работать) |
| Незаконченная установка (`PartialInstall`) | «Прошлая установка не завершилась» → кнопка «Очистить и поставить заново» (Uninstall → Install) |
| Чужой xray (`HasForeignXray`) | Отказ с объяснением и командой для ручного удаления. Переустановка поверх чужого xray в 3a не делается (*решение исполнителя*: автоматически удалять то, что ставили не мы, опасно; миграция — позже) |
| Неверный пароль / ключ | «Не удалось войти: проверьте пароль» |
| Пользователь без беспарольного sudo (`ErrSudoPassword`) | Объяснение: нужен root или беспарольный sudo |
| Отпечаток хоста изменился (`ErrHostKeyMismatch`) | Красное предупреждение, дальше не идём |
| Нет соединения / таймаут SSH | Совет проверить IP, порт и что порт SSH не закрыт фаерволом хостера |
| Окно закрыли посреди установки | При следующем подключении к этому серверу сработает строка «Незаконченная установка» |

### 4.4 Главный экран подключения

По макету A из основной спеки: большая круглая кнопка, статус
(«Отключено» / «Подключаюсь…» / «Подключено» / ошибка понятными словами),
таймер, карточка «Режим: Умный / Всё через VPN» (переключатель). Движок —
`internal/engine` (mihomo + xray), тот же, что под `wayveil connect`.

- **Права:** при первом подключении, если у mihomo нет capability, —
  однократный `pkexec setcap` (`engine.GrantCaps`), системный графический
  диалог. Дальше без запросов.
- Закрытие окна **не** отключает VPN: движок — отдельные процессы
  (`run.json`). При следующем запуске GUI подхватывает состояние.
- Нижней панели вкладок в 3a нет (вкладка одна). Она появится вместе с
  вкладкой устройств.

### 4.5 Язык

Только английский (решение автора). Ошибки из Go-пакетов показываются
человеческими английскими фразами, а не кодами вроде `port_busy`.

### 4.6 Тестирование

- `internal/gui.App` тестируется обычными Go-тестами с поддельными
  зависимостями (как `cmd/wayveil-dev`): порядок вызовов, события шагов,
  пограничные случаи из 4.3, что пароль не попадает в события и логи.
- Интеграционный тест (`-tags integration`): `App` проходит мастер против
  тестового контейнера-сервера (`testenv`) — вход по паролю, Precheck,
  таргет, установка, «Я», затем «Взять управление» и «Переустановить».
- Фронтенд держится тонким (только отображение и вызовы `App`); логику
  состояний экрана — в TS-модулях с юнит-тестами (vitest).
- Ручная приёмка — у автора на реальном VPS (раздел 6).

### 4.7 Решения исполнителя по итогам проверки документа

- **«Взять управление»** требует добавить ключ приложения в `authorized_keys`
  на уже установленном сервере. Для этого появляется маленький серверный
  скрипт/функция (`server.Adopt`), который добавляет ключ **и записывает его
  в манифест**, чтобы «Удалить Wayveil» потом убрал и его.
- **Zip xray для сервера** лежит рядом с бинарником GUI (как mihomo), для
  amd64 и arm64: `make app` кладёт `build/Xray-linux-64.zip` и
  `build/Xray-linux-arm64-v8a.zip` (обе с проверкой SHA-256). Если нужного
  zip нет, сервер скачивает сам (поведение установщика уже такое).
- **Вход в мастер, когда профиль подключения уже есть:** на главном экране
  маленькое меню «⋯» с пунктами «Настроить свой сервер» и «Заменить ссылку».
  Без него критерий 6 не проверить.
- **Один сохранённый сервер владельца** в 3a; несколько серверов — позже.

## 5. Остаётся на усмотрение исполнителя

Точные тексты на экранах (в духе основной спеки), анимации, раскладка
внутри экранов в рамках макета, формат событий между Go и фронтендом,
обработка изменения размера окна, где именно хранится профиль подключения
(используются существующие `clientstore` / каталоги `appdir`).

## 6. Критерии приёмки 3a

1. `make app` на Linux собирает `build/wayveil-gui`; приложение запускается
   без терминальных шагов.
2. Без сохранённых профилей открывается экран «Paste a connection link».
3. На свежем VPS с Ubuntu 24.04 автор проходит мастер от IP и пароля до
   экрана «Готово» без ручных действий, быстрее 3 минут (критерий 1 основной
   спеки).
4. Поиск таргета идёт в фоне: «Далее» доступна сразу, найденные сайты
   появляются по ходу.
5. «Подключиться» с экрана «Готово» включает VPN; проверки из критерия 5
   основной спеки проходят (youtube/instagram/chatgpt через VPN, 2ip.ru —
   российский IP). Права запрашиваются не больше одного раза.
6. Повторный запуск мастера на том же сервере предлагает «Взять управление» /
   «Переустановить»; оба пути работают.
7. Пароль не появляется ни в файлах приложения, ни в его логах.
8. Окно ~380×640, стиль A, все тексты интерфейса на английском.
